Concurrency is about managing multiple in-progress tasks. Parallelism is about doing work at the same time on different CPU cores. The right tool depends on the bottleneck.

## Threads for waiting

Threads can overlap I/O waits such as network or file operations. They share memory, which makes communication easy but creates races. Protect shared mutable state with a lock or, better, reduce the amount of shared state.

## Processes for CPU work

CPU-heavy pure Python threads are limited by the Global Interpreter Lock (GIL) in common CPython builds. Separate processes can use multiple cores, but data must be serialized between processes and process startup has a cost. Use a process pool for independent CPU-bound tasks large enough to justify that cost.

## asyncio for cooperative I/O

An `async def` function returns a coroutine. `await` gives the event loop a chance to run another task while the current task waits:

```python
async def fetch_all(client, urls):
    return await asyncio.gather(*(client.get(url) for url in urls))
```

Async code only helps when the operations cooperate with the event loop. Calling blocking file or CPU work directly inside an async function still blocks every other task.

## Cancellation and backpressure

Bound concurrency with a semaphore or queue. Handle cancellation so resources are released. A producer that creates work faster than consumers can handle it needs backpressure, otherwise memory grows without limit.

> [!TIP]
> Measure the operation first. “Async” is not a speed spell; it is a coordination model with cancellation, error, and resource-lifetime rules.
