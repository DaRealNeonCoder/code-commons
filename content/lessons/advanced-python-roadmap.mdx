This course assumes you completed [Intro to Python](/courses/intro-to-python). You should be comfortable with functions, collections, file/module basics, exceptions as ordinary failures, and decomposing a small program into helpers. We will briefly reuse those ideas, not reteach them.

The goal is to build programs that remain understandable as they grow. Each stage adds a capability and a reason to use it:

| Stage | Question | Skills |
| --- | --- | --- |
| Python's model | What does a name point to? | identity, mutability, hashing, memory behavior |
| Expressive code | How can repeated data flow stay clear? | comprehensions, unpacking, iterators, generators |
| Reusable behavior | How can functions add behavior without copying code? | closures, decorators, context managers |
| Domain design | How should a program represent real things? | composition, inheritance, dataclasses, protocols |
| Reliability | How do we know changes did not break behavior? | exceptions, type hints, tests, mocks |
| Delivery | How does code become a reusable tool? | packages, environments, CLI, SQLite |
| Scale | What should run concurrently or faster? | threads, processes, asyncio, profiling |
| Integration | Can the pieces work together? | a tested document indexer/search CLI |

## A project-first loop

For every new feature:

1. write a small behavior example;
2. choose the narrowest interface that expresses it;
3. implement the simplest version;
4. test normal and failure cases;
5. measure before optimizing;
6. document the boundary that another module will use.

Advanced Python is not a contest to use the most language features. A generator, decorator, class, or async task is valuable when it makes a real constraint easier to express.
