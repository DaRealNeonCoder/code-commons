Before fitting a model, understand the table it will see. A single average is a useful baseline, but it hides variation. A fair evaluation also depends on keeping some examples out of training.

## Mean, spread, and a baseline

The **mean** is the usual average. The **standard deviation** summarizes a typical distance from that average:

```text
mean = sum(values) / n
variance = sum((value - mean)²) / n
standard deviation = sqrt(variance)
```

The mean is a simple regression baseline: predict the training-set mean for every new row. A useful model should beat that baseline on data it has not seen. A **z-score** says how many standard deviations a value is above or below the mean:

```text
z = (value - mean) / standard deviation
```

## Three data roles

Use different rows for different decisions:

1. **Training set:** the model changes its parameters using these labels.
2. **Validation set:** we compare model settings, such as learning rates or hidden-unit counts.
3. **Test set:** we report a final score once, after choices are finished.

If the same row helps choose a setting and then proves that setting works, the score is optimistic. That is not a minor bookkeeping issue: it changes what the score means.

## Leakage is a shortcut, not learning

**Data leakage** happens when information that would not be available at prediction time sneaks into training. A feature that directly copies the answer can produce a perfect score without teaching the model a useful pattern. Split first, calculate training statistics only from the training set, and apply those fixed statistics to validation and test rows.

> [!TIP]
> A test score answers “How did this finished choice work on new examples?” It does not answer “Which choice should I make?” That is the validation set's job.
