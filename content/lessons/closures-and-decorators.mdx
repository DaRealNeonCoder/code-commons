Intro to Python used functions as named blocks. Python also lets you store a function in a variable, pass it to another function, and return a new function. This is the basis of callbacks, closures, and decorators.

## Closures retain an enclosing value

```python
def make_multiplier(factor):
    def multiply(value):
        return value * factor
    return multiply

times_three = make_multiplier(3)
times_three(4)  # 12
```

The returned function remembers `factor` even after `make_multiplier` has returned. That retained environment is a closure. Use `nonlocal` when the inner function must reassign a captured name, such as a counter.

## Decorators wrap a function

A decorator receives a function and returns a replacement with an extra behavior:

```python
from functools import wraps

def announce(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        print("starting")
        result = function(*args, **kwargs)
        print("finished")
        return result
    return wrapper
```

`@announce` is syntax for replacing the function with `announce(function)`. Preserve the original name and docstring with `functools.wraps`. A decorator should not accidentally swallow return values or exceptions.

## When to use them

Decorators are useful for cross-cutting behavior such as timing, authorization, retries, caching, or logging. A closure is often the simpler choice when you only need a configured function. If a decorator makes the call signature or control flow mysterious, a normal helper may be better.

> [!WARNING]
> A decorator runs when the function is defined, while the wrapper runs when the function is called. Keeping those moments distinct prevents surprising setup behavior.
