In Intro to Python, assignment was introduced as storing a value under a name. More precisely, a name refers to an object. Understanding that distinction explains aliasing, mutation, and many bugs that appear when a program grows.

## Equality is not identity

`==` asks whether two objects have equal values. `is` asks whether two names refer to the same object:

```python
first = [1, 2]
second = first
third = [1, 2]

first == third  # True: equal contents
first is third  # False: different list objects
first is second # True: one object, two names
```

Mutating `first` also changes what `second` sees because both names share the list. Rebinding `first` to a new list would not rebind `second`.

## Copy the boundary you need

`copy.copy()` makes a shallow copy: the outer container is new, but nested objects are still shared. `copy.deepcopy()` recursively copies supported nested values. Prefer explicit construction when the data shape is small; it documents which parts should be independent.

Mutable default arguments are another aliasing trap. A default list is created once when the function is defined, not once per call:

```python
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

## Hashing and dictionaries

Dictionary keys and set members need a stable hash and equality behavior. Mutable lists cannot be keys because changing their contents would change the lookup identity. Immutable tuples can be keys when all their members are hashable.

Python manages object memory automatically through reference counting plus a cyclic garbage collector. You usually should not manage memory manually; you should release unnecessary references and avoid retaining huge objects longer than needed.

> [!WARNING]
> Do not use `is` for ordinary value comparison. Identity checks are appropriate for singletons such as `None`; use `==` when you mean equal contents.
