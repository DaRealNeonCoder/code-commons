A language model's learned parameters are not a live database. Retrieval-augmented generation (RAG) adds a data path: find relevant passages, place them in a prompt, and ask the generator to answer using that context.

## The RAG loop

1. Split source documents into chunks with useful boundaries.
2. Embed chunks and store vectors with IDs and source metadata.
3. Embed the query and retrieve candidates by similarity.
4. Optionally rerank candidates with a stronger model.
5. Construct a bounded prompt containing the selected passages and instructions.
6. Generate an answer with citations or abstain when evidence is insufficient.

Retrieval and generation are separate failure modes. A fluent answer can be wrong because the retriever missed the source, because the prompt allowed unsupported synthesis, or because the model ignored the evidence.

## Evaluate the whole path

Measure retrieval recall at `k`, answer correctness, citation support, latency, and cost. Include questions with no answer in the corpus. Protect against prompt injection in retrieved documents, enforce access controls before retrieval, and treat document metadata as untrusted input.

## Grounding is a product contract

Tell the generator what counts as evidence, how to cite it, and what to do when passages conflict or do not answer the question. Return source IDs alongside text so a user can inspect the evidence. Keep retrieval logs privacy-aware and delete or restrict documents according to their source policy.

> [!TIP]
> RAG does not “remove hallucinations.” It creates an opportunity for the model to use evidence. Retrieval recall, prompt design, generation behavior, and citation validation all need checks.
