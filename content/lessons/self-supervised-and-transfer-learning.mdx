Labels are expensive, but raw data is often plentiful. **Self-supervised learning** creates a target from the input itself: predict a masked token, match two augmented views, or predict the order of pieces. The learned encoder can then provide features for a labeled downstream task.

## Transfer learning choices

Start with a pretrained backbone and choose how much to update:

- **Frozen features:** train a new head while keeping the backbone fixed. This is cheap and reduces overfitting on a small labeled set.
- **Partial fine-tuning:** unfreeze later blocks and use a smaller learning rate for pretrained layers.
- **Full fine-tuning:** update the entire model when the new domain is sufficiently different and data supports it.

Preprocessing, label definitions, and input distributions must match the assumptions of pretraining. A backbone can transfer a shortcut as easily as a useful feature.

## Data augmentation is a hypothesis

An augmentation should preserve the label. Cropping a photo may be safe for object category but unsafe for a task where position is the label. Compare augmentation policies on validation data and inspect examples; “more augmentation” is not automatically better.

> [!TIP]
> Fine-tuning is still training. Keep a clean downstream validation/test split, fit preprocessing on training data only, and compare against a simple frozen-feature baseline.
