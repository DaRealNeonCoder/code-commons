The previous lesson used dot products as a matching score. Two ideas make that score easier to reason about: a vector's **length** and the **shape** of a collection of vectors.

## Length is distance from the origin

For a two-dimensional vector `[x, y]`, the length (or **Euclidean norm**) is:

```text
||v|| = sqrt(x² + y²)
```

This is the Pythagorean theorem. The vector `[3, 4]` has length `5`, because `sqrt(3² + 4²) = 5`. A norm is never negative. The zero vector has length zero and no direction, which is why cosine similarity needs a special case for it.

Scaling a vector changes its length but not its direction: `[1, 2]` and `[2, 4]` point the same way. Cosine similarity divides a dot product by both lengths to focus on that direction.

## Shape is a safety rule

Write a matrix's shape as `(rows, columns)`. A matrix with two rows and three columns has shape `(2, 3)`:

```text
X = [[area, rooms, age],
     [area, rooms, age]]       shape: (2, 3)
```

Each row is one example and each column is one feature. Matrix-vector multiplication works when the vector has one weight per column:

```text
(2, 3) × (3,) → (2,)
```

The result has one weighted sum per row. The inner dimensions, `3` and `3`, match. If a table has four feature columns, a weight vector of length three is a type error in disguise: one feature has no weight.
