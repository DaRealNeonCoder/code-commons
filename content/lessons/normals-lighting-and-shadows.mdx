# A normal describes a surface direction

The vertex shader passes a normal to the fragment shader. Normalize it before
using dot products. For a light direction `L` and normal `N`, Lambert diffuse
lighting is `max(dot(N, L), 0.0)`. A specular term compares the reflected light
direction with the view direction:

```glsl
vec3 N = normalize(v_normal);
vec3 L = normalize(vec3(-0.4, 0.8, 0.6));
vec3 V = normalize(u_cameraPosition - v_worldPosition);
float diffuse = max(dot(N, L), 0.0);
vec3 reflected = reflect(-L, N);
float specular = pow(max(dot(V, reflected), 0.0), 32.0);
vec3 color = u_color * (0.18 + 0.82 * diffuse) + vec3(specular);
```

The current engine has depth testing but no shadow-map or multi-pass API.
Teach shadow principles with a binary visibility term in a ray-marched shader,
or use a stylized ground-darkening approximation in a mesh shader. Do not add a
fake `engine.shadows` call: it is not part of the supported API.

## Checkpoint and project

The [lighting puzzle](/shaders/programmable-3d-lighting) requires a plane
whose brightness follows its normal under a fixed light. Match ambient plus
diffuse first, then add a tight specular highlight without changing the base
color.

**Project — light study:** render a cube, expose light direction as a CPU
uniform, and let pointer input rotate it. Include a second version that uses
the fragment-only ray-marching workflow to demonstrate a soft shadow. Compare
what each path can and cannot share.
