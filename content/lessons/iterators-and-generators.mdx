An iterable can produce an iterator. An iterator remembers where it is and supplies the next item when Python calls `next()`.

```python
items = iter([10, 20])
next(items)  # 10
next(items)  # 20
```

When there are no more items, an iterator raises `StopIteration`. A `for` loop handles that protocol for you.

## Generators pause at `yield`

A function containing `yield` returns a generator object. Its body runs until the next `yield`, pauses, and resumes from that point when asked for another value:

```python
def positive_numbers(values):
    for value in values:
        if value > 0:
            yield value
```

Generators are valuable when the input is large, infinite, or expensive to produce. They do not make the work free; they move the work to consumption time and avoid storing all results.

## Compose a pipeline

Keep each stage narrow:

```python
events = read_events(file)
valid = (event for event in events if event.ok)
names = (event.name.upper() for event in valid)
for name in names:
    print(name)
```

Be careful with one-shot iterators: after consumption, they are exhausted. If you need to traverse data several times, a list or a repeatable iterable may be the correct choice.

> [!TIP]
> Choose a generator when “produce one more item” is a useful boundary. Choose a list when you need random access, repeated traversal, or the full result immediately.
