An MLP can feel like a wall of symbols when every weight changes at once. Start with one neuron and two features. The same four steps will later be repeated for many neurons:

1. **Forward pass:** calculate `z = w · x + b`.
2. **Activation:** turn the score into an output with the sigmoid.
3. **Error:** compare the output with the label.
4. **Update:** move the parameters in a direction that should reduce the error.

## Forward pass

For features `x = [x₁, x₂]`, weights `w = [w₁, w₂]`, and bias `b`:

```text
z = w₁x₁ + w₂x₂ + b
output = sigmoid(z) = 1 / (1 + exp(-z))
```

The output is between `0` and `1`. We can interpret it as the model's confidence in class `1`; a threshold such as `0.5` turns it into a hard class, but the smooth probability is what makes a useful gradient possible.

## One update, carefully

For a sigmoid output trained with binary cross-entropy, the output error simplifies to:

```text
error = output - label
gradient_w[i] = error × x[i]
gradient_b = error
```

Then subtract `learning_rate × gradient` from each parameter. The sign matters. If the model is too confident in class `1` for a label of `0`, `error` is positive and the update lowers the score.

## Why this prepares us for backpropagation

With one neuron, every parameter receives a direct signal. In a layer of neurons, each neuron has its own weights and bias. In a network with hidden layers, a hidden neuron's error is indirect: it must be carried backward through the later layer. That is backpropagation, not a new kind of forward pass.

> [!TIP]
> Write down `z`, the activated output, and `error` before writing update code. Most beginner bugs are a missing bias, a wrong sign, or using a hard threshold before calculating the gradient.
