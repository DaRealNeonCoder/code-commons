# Opt in to programmable 3D

Select **Programmable 3D scene** when a lesson needs CPU-side scene code. The
CPU file must define `setup(engine)`. A minimal object is:

```js
function setup(engine) {
  const cube = engine.scene.add({
    geometry: engine.geometry.cube(),
    material: engine.material({ uniforms: { u_color: [0.2, 0.7, 1.0] } }),
    position: [0, 0, 0],
  });
  engine.camera.position.set(0, 0, 4.5);
  return { update({ delta }) { cube.rotation.y += delta; } };
}
```

The three files are deliberately visible: CPU JavaScript, vertex GLSL, and
fragment GLSL. The engine supplies `u_model`, `u_view`, `u_projection`,
`u_cameraPosition`, `u_time`, and `u_resolution`. Material uniforms can be
numbers or numeric vectors/matrices.

## Checkpoint and project

Open [Programmable 3D Cube](/shaders/programmable-3d-cube). Change only one
file at a time: first the CPU rotation, then the vertex position, then the
fragment color. A valid result has one centered cube, visible depth, and a
rotation driven by `delta`, not by a fixed frame count.

This API is intentionally small: built-in cube, plane, and triangle geometry;
custom indexed geometry; one perspective camera; scene add/remove/clear; and
normalized pointer input. It is enough for graphics fundamentals without
requiring a game loop or asset pipeline.
