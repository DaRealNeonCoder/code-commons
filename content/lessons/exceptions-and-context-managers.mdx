The Intro course used debugging and ordinary errors. Larger programs need deliberate failure design: which problems should the caller handle, which should stop the operation, and what cleanup must happen even when an error occurs?

## Catch narrowly, explain clearly

```python
try:
    amount = float(text)
except ValueError as error:
    raise InvalidRecord("amount is not a number") from error
```

Catch the exception you expect, not every exception. A bare `except` can hide programming bugs. `raise ... from error` preserves the original cause while presenting a domain-level message.

Custom exceptions communicate the boundary of a module:

```python
class InvalidRecord(Exception):
    pass
```

Callers can catch `InvalidRecord` without knowing whether parsing used a file, JSON, or a database.

## Context managers guarantee a boundary

The `with` statement calls `__enter__` and then guarantees `__exit__`, even if the body raises. Files use this protocol, but it also applies to locks, temporary directories, transactions, and test fixtures.

```python
class Audit:
    def __enter__(self):
        self.events = []
        return self
    def __exit__(self, exc_type, exc, traceback):
        save_events(self.events)
```

Return `False` or `None` from `__exit__` to let an exception propagate. Suppress an exception only when the context manager has fully handled it and that behavior is part of its contract.
