Classes are useful when data and the operations that protect its rules belong together. They are not automatically better than functions and dictionaries. Choose a class when an object has a meaningful state, invariants, and behavior that should travel together.

## Dataclasses make records explicit

```python
from dataclasses import dataclass

@dataclass
class Book:
    title: str
    available: bool = True
```

The decorator supplies an initializer and readable representation. Add methods when the class can enforce a rule, such as `checkout()` refusing an unavailable book.

## Composition before inheritance

Composition means one object contains another object:

```python
class Library:
    def __init__(self, catalog):
        self.catalog = catalog
```

It keeps responsibilities separate and lets you replace the catalog implementation. Inheritance can be useful for a stable “is-a” relationship, but deep hierarchies make behavior harder to find. Prefer small interfaces and compose collaborators.

## Polymorphism is about behavior

If several objects provide a `total()` method, a checkout function can call `item.total()` without checking every concrete type. This duck-typed style is often more flexible than a long chain of `isinstance` checks. The next typing lesson shows how to document that expected behavior with a protocol.
