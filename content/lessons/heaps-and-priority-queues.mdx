A **priority queue** removes the most urgent item rather than the oldest item. A min-heap gives a compact implementation: the smallest priority is at the root, while the rest of the items only need to satisfy a local parent-child rule. A heap is not a fully sorted list; it is just ordered enough to expose the next item quickly.

## Array representation

Store a complete binary tree in a zero-based list. For an item at index `i`, its children are at `2 * i + 1` and `2 * i + 2`, and its parent is at `(i - 1) // 2`. There are no pointers or empty gaps between levels.

The min-heap invariant is: every parent priority is less than or equal to each existing child's priority. To insert, append at the end and **sift up** while the new item is smaller than its parent. To remove the minimum, save the root, move the last item to the root, and **sift down** by swapping with the smaller child until the invariant returns:

```python
def push(heap, item):
    heap.append(item)
    child = len(heap) - 1
    while child > 0:
        parent = (child - 1) // 2
        if heap[parent] <= heap[child]:
            break
        heap[parent], heap[child] = heap[child], heap[parent]
        child = parent


def pop_min(heap):
    if not heap:
        return None
    heap[0], heap[-1] = heap[-1], heap[0]
    result = heap.pop()
    child = 0
    while True:
        left = 2 * child + 1
        right = left + 1
        smallest = child
        if left < len(heap) and heap[left] < heap[smallest]:
            smallest = left
        if right < len(heap) and heap[right] < heap[smallest]:
            smallest = right
        if smallest == child:
            break
        heap[child], heap[smallest] = heap[smallest], heap[child]
        child = smallest
    return result
```

The height of a complete tree is O(log n), so `push` and `pop_min` take **O(log n)** time. Looking at the root is **O(1)**. Repeatedly inserting n items costs O(n log n), while bottom-up heap construction can build a heap in O(n). The array uses **O(n) space**.

## Priorities, ties, and practical queues

A heap item can be a tuple such as `(priority, sequence, task)`. Comparing the sequence number after priority makes equal-priority tasks FIFO and avoids relying on task names as an accidental tie-breaker. A max-priority queue can store negative priorities or reverse its comparison. Python's `heapq` supplies a tested min-heap; implementing the operations once makes its invariant easier to understand.

## Boundaries and invariants

An empty heap has no root, so `peek` or `pop` needs a defined empty result. A one-item heap becomes empty after its only pop. During sift-down, choose the smaller existing child; comparing a missing right child is an indexing error. Duplicate and negative priorities are valid. If stable tie behavior matters, keep a monotonic sequence field in each item.

The complete-tree shape is another invariant: after every push, the new item is at the next open level-order position; after every pop, the last item fills the root's old position. Sifting repairs priority order without changing that shape. Do not confuse a heap with a binary search tree: a heap only orders parent against children, so an in-order traversal is not sorted and arbitrary search is still O(n).
