An **SR latch** has two control inputs:

- **S**, for set: ask the latch to store `1`.
- **R**, for reset: ask the latch to store `0`.

When neither control is active, the latch holds its previous output. That “hold” row is the reason it can remember. A simplified active-high table looks like this:

| S | R | Next Q |
| ---: | ---: | ---: |
| 0 | 0 | hold |
| 1 | 0 | 1 |
| 0 | 1 | 0 |
| 1 | 1 | avoid |

The last row is not a useful command: asking to set and reset at the same time makes the intended next state ambiguous. Different physical designs use different conventions, so beginners should treat it as an invalid input combination here.
