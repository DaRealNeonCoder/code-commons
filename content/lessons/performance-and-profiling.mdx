Performance work starts with a user-visible target and a measurement. “This feels slow” is a prompt to profile, not a reason to rewrite every loop.

## Complexity is a prediction

An `O(n)` scan usually grows more gently than an `O(n²)` nested comparison. Dictionary and set membership is typically average `O(1)`, while list membership is `O(n)`. Constants, input shape, memory locality, and I/O can still dominate at realistic sizes.

## Profile before optimizing

Use `time.perf_counter()` for a controlled elapsed-time measurement and `cProfile` for a function-level view. Measure representative inputs, warm up if relevant, and compare the same output and correctness checks before and after a change.

## Memory and caching

Generators avoid storing a full intermediate result. `__slots__` can reduce per-instance dictionary overhead for specialized classes, but it changes flexibility and should be measured. Caching is useful when the same expensive input repeats; it is harmful when keys are unbounded or values become stale. Define a cache size or invalidation policy.
