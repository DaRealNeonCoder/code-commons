Binary classification has two outcomes. A digit recognizer has several possible outcomes, so it needs a probability for every class. The model first produces one raw **logit** per class, then softmax turns the collection into a probability distribution.

## One-hot labels

If the correct class is `2` among three classes, a one-hot label is:

```text
[0, 0, 1]
```

It has one `1` at the correct index and `0` elsewhere. This is a convenient numeric way to say which class is correct; it does not mean the classes are ordered quantities.

## Stable softmax

```text
softmax(zᵢ) = exp(zᵢ) / (exp(z₁) + exp(z₂) + ...)
```

The probabilities are non-negative and add to `1`. To avoid overflowing when logits are large, subtract the largest logit first:

```python
largest = max(logits)
exponentials = [math.exp(value - largest) for value in logits]
total = sum(exponentials)
probabilities = [value / total for value in exponentials]
```

Subtracting the same number from every logit does not change the relative probabilities. It only makes the intermediate exponentials safer.

## Cross-entropy rewards calibrated confidence

For a one-hot label, cross-entropy loss is:

```text
loss = -log(probability of the correct class)
```

Predicting the correct class with probability `0.9` gives a small loss. Predicting it with probability `0.01` gives a large loss, even if it was the second-largest score. This teaches the model not only to rank the correct class first, but to put more probability on it.

Here `log` means the natural logarithm: it asks which power of `e` produces a number. For probabilities, `log(1) = 0` and `log` becomes more negative as the probability approaches zero. The negative sign therefore makes a confident wrong answer expensive while keeping a confident correct answer near zero loss.

For softmax followed by cross-entropy, the gradient with respect to each logit is especially simple:

```text
gradient = probabilities - one_hot_label
```

The digit recognizer will use exactly this signal, first for one example and then averaged over a mini-batch.

> [!TIP]
> Logits are not probabilities. Keep the stages named: linear scores → stable softmax → loss → gradient.
