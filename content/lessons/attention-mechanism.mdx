Attention lets a position look at other positions and choose how much each one should contribute. Instead of compressing the entire past into one recurrent state, it computes a weighted combination of available **values**.

## Query, key, value

For a query `q`, keys `kᵢ`, and values `vᵢ`:

```text
scoreᵢ = q · kᵢ / sqrt(dₖ)
weights = softmax(scores)
output = sum(weightsᵢ × vᵢ)
```

The query asks what this position needs. A key describes what each candidate offers. The value is the content that gets mixed. The scale `sqrt(dₖ)` keeps dot products from becoming too large as the key dimension grows.

## Self-attention and masks

In self-attention, queries, keys, and values come from the same sequence. A language model uses a causal mask so position `t` cannot inspect future tokens. Encoder-style attention may allow every position to see every other position. Multi-head attention runs several smaller projections in parallel, letting heads specialize in different relationships.

## Attention is not explanation by default

High attention weight tells you which values contributed to one computation, not necessarily why a model made a human-level decision. Test causal claims with interventions, ablations, or counterfactual inputs. Also remember that attention cost grows with the number of pairwise token interactions.

> [!TIP]
> Keep the three projections distinct in code. Mixing up query, key, and value tensors can still produce numbers with the right shape while destroying the intended behavior.
