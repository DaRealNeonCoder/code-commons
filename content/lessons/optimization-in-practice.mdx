The Intro course used a fixed learning rate and the update `parameter -= rate × gradient`. That is the foundation, not the only option. Deep networks often have uneven curvature, noisy mini-batch gradients, and parameters that need different step sizes.

## Learning-rate schedules

A schedule changes the learning rate during training. A warm-up starts small while activations and gradients settle; decay then takes smaller steps near a useful solution. Two simple schedules are:

```text
linear decay: rate(t) = start × (1 - t / total_steps)
cosine decay: rate(t) = minimum + 1/2 × (start - minimum) × (1 + cos(πt / total_steps))
```

The schedule is a hyperparameter choice. Plot it before training so a surprising loss curve is not confused with a mysterious model failure.

## Momentum remembers direction

Momentum keeps an exponentially smoothed velocity:

```text
velocity = β × velocity + (1 - β) × gradient
parameter = parameter - rate × velocity
```

Repeated gradients in the same direction accumulate; alternating noise is damped. The `β` value controls how much history remains.

## Adam adapts each coordinate

Adam keeps both a first moment and a second moment:

```text
m = β₁m + (1 - β₁)g
v = β₂v + (1 - β₂)g²
parameter -= rate × (m̂ / (sqrt(v̂) + ε))
```

The hats correct the early bias toward zero. Adam is convenient, not magic: its learning rate still matters, and adaptive steps do not remove the need for validation.

## Initialization is part of optimization

If every hidden unit starts with identical weights, they receive identical gradients and learn the same feature. Small random values break symmetry. Xavier/Glorot initialization scales a weight by the input and output widths; He initialization uses a larger scale for ReLU-like activations. The principle is to keep activations and gradients from immediately exploding or vanishing.
