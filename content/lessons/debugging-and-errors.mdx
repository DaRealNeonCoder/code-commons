Errors are feedback about the program's current behavior. Debugging means using that feedback to find the smallest incorrect assumption and test a correction.

## Three useful categories

- **SyntaxError:** Python cannot parse the code, often because of a missing colon, quote, or parenthesis. Fix the line Python points to, then check the line before it too.
- **Runtime error:** the code parsed, but an operation failed while it ran. `NameError` means a name is not defined; `TypeError` means an operation received an incompatible type; `IndexError` means a sequence position is outside its valid range.
- **Logic error:** the program runs but produces the wrong answer. Add a small print, trace the values, and compare the first unexpected value with your hand calculation.

## Read a traceback from the bottom

The last line usually names the error and explains it. The lines above show the call path and the file/line where the failure surfaced. Do not treat the traceback as a wall of text: locate the final error type, inspect the indicated line, and ask what types and values reached it.

## A systematic loop

1. Reproduce the smallest failing input.
2. State the expected result.
3. Inspect one intermediate value with `print(type(value), value)`.
4. Change one thing.
5. Re-run the same input, then test an edge case.

> [!WARNING]
> Do not “fix” an error by hiding it with a broad workaround you do not understand. First learn what value or assumption caused the failure.
