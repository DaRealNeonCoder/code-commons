The capstone is a local document indexer and search tool. It is deliberately modular rather than enormous. Start with a pure parser, then add one boundary at a time.

## Suggested architecture

```text
document_tool/
  parsing.py      # text → Document records
  indexing.py     # records → term → document IDs
  storage.py      # save/load snapshots or SQLite rows
  search.py       # query → ranked results
  cli.py          # argparse and formatting
tests/
```

Use a dataclass for a document record. Use a generator to walk paths without loading every file. Raise a custom exception for malformed metadata. Test parsing and search as pure functions before testing filesystem and database adapters.

## Add concurrency only after correctness

Index files independently with a bounded thread pool when file reads dominate. Keep errors associated with their path, and make output deterministic by sorting results before displaying them. If profiling shows tokenization is CPU-heavy, compare a process pool—but measure serialization costs first.

## A realistic definition of done

- `index` accepts a directory and records document IDs, paths, and terms.
- `search` returns matching document paths in a stable order.
- malformed files produce a useful error without losing valid files.
- the index can be saved and loaded.
- unit tests cover parsing, empty queries, duplicate terms, and failures.
- a benchmark records file count, runtime, and memory assumptions.
