Real applications need an interface and durable state. Python's standard library is enough to build a useful local tool before adding a web framework or an external database.

## Keep the CLI thin

`argparse` turns command-line arguments into a structured namespace. The CLI should validate user-facing options and call application functions; it should not contain every parsing, query, and formatting detail.

```python
parser.add_argument("command", choices=["add", "search"])
parser.add_argument("--term", default="")
args = parser.parse_args()
```

This makes help output and invalid commands predictable. Test the domain functions independently of `sys.argv`, then add a small number of CLI integration tests.

## SQLite is a useful local boundary

```python
import sqlite3

with sqlite3.connect("records.db") as connection:
    connection.execute("CREATE TABLE IF NOT EXISTS records (id INTEGER PRIMARY KEY, text TEXT)")
    connection.execute("INSERT INTO records(text) VALUES (?)", (text,))
    connection.commit()
```

Always parameterize values instead of joining strings into SQL. Keep schema creation and query functions in a persistence module. A transaction gives a group of writes all-or-nothing behavior; context managers help close connections and roll back failures according to the chosen policy.

## JSON is an interchange format

Use `json` when a human-readable snapshot or message is more appropriate than relational queries. Validate the shape when loading external JSON; a syntactically valid document can still violate the application's schema.
