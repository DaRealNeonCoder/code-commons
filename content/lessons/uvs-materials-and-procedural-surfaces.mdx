# Surface data without an asset pipeline

The built-in plane and cube include UV coordinates. The vertex shader passes
`a_uv` to `v_uv`; the fragment shader can use the interpolated value to create
stripes, checkerboards, gradients, or other **procedural materials**:

```glsl
float stripe = step(0.5, fract(v_uv.x * 8.0));
vec3 color = mix(u_color, vec3(1.0), stripe * 0.35);
gl_FragColor = vec4(color, 1.0);
```

This runner currently has no image loader, sampler, texture object, or
filtering API. You can learn what texture coordinates mean and how a shader
would sample them, but you should not pretend that `sampler2D` works here.
Procedural surfaces are the supported equivalent.

Conceptually, a texture **sample** looks up a color at a UV coordinate. Nearest
filtering chooses one texel; linear filtering blends nearby texels. Repeated
or clamped addressing decides what happens outside `[0, 1]`. Those choices
change the image at edges and at different scales. In a renderer with textures
the fragment code would declare `sampler2D` and call `texture2D` (or `texture`
in newer GLSL); in this runner, replace that lookup with a mathematical
function of `v_uv` so the experiment stays executable.
