Python gives you several collection types because programs ask different questions. Choosing the right one makes the code clearer and often avoids extra work.

| Need | Good first choice | Why |
| --- | --- | --- |
| ordered items that may change | list | position and repeated values matter |
| a fixed group of related values | tuple | the group should not change |
| membership and uniqueness | set | duplicates disappear and membership is direct |
| look up a value by a key | dictionary | each key maps to a value |

## Nested data follows the shape of the problem

A class roster might be a list of names. Scores by student might be a dictionary whose values are lists:

```python
scores = {
    "Mina": [8, 10],
    "Leo": [7, 9]
}
```

Choose the outer structure by the operation you need first. If you ask “what are Mina's scores?”, a dictionary is natural. If you ask “in what order were submissions received?”, a list is natural.

## Convert deliberately

It is normal to move between structures:

```python
names = ["Ada", "Ada", "Lin"]
unique_names = set(names)
ordered_again = sorted(unique_names)
```

The conversion may discard duplicates or change ordering. Make that trade-off visible in the variable name and only convert when it serves the next operation.

> [!TIP]
> A data structure is a decision about meaning. Ask whether order, changeability, duplicates, membership, or key-based lookup is the important property.
