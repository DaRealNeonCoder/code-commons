Sort the `[key, label]` records in place by their integer key using insertion-sort logic. Equal keys must keep their original label order, so the result for `2:first 1:low 2:second` starts with `low first second`. Do not use Python's built-in sorting methods. The empty input is valid.

The intended invariant is that the records before the current index are sorted and are a permutation of the records originally seen. Shift only records with a strictly larger key; shifting equal keys would make the algorithm needlessly unstable. The expected time is O(n²) in the worst case and O(n) for already sorted input, with O(1) extra space beyond the list.
