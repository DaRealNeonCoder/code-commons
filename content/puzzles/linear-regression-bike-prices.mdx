Complete `dot`, `predict`, `mean_squared_error`, and `train`. Each data row contains its feature values followed by the real used-bike price. The final line contains a learning rate and an epoch count.

Start every weight and the bias at zero. For each epoch, calculate the prediction error for every row, then use these MSE gradients to update the parameters:

```text
gradient_w[j] = 2 × average(error × feature[j])
gradient_b   = 2 × average(error)
```

At the end, print `beat` only when your model's MSE is smaller than the baseline that always predicts the average bike price. Use plain Python lists and loops; the dot product is the small, readable version of `Xw` for one row at a time.

Keep the feature order unchanged. If a model was trained with weight in kilograms and distance in kilometers, silently replacing kilometers with meters changes the scale and can make its predictions wrong. That is the scaling bug to watch for when you work with real data.

> [!TIP]
> For a row `[a, b]` and weights `[u, v]`, the model is `a × u + b × v + bias`. MSE is the average of the squared differences between that result and each target.
